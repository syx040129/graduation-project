## 项目概述与功能状态

CareerNova（智聘 AI）是前后端分离的招聘毕业设计项目，面向求职者 USER、企业 COMPANY 和管理员 ADMIN。AI 业务包括简历分析、岗位匹配、岗位推荐、简历优化、模拟面试和招聘助手，另有企业候选人分析。

**交付结论：本地 Mock 演示有条件交付；未达到无条件完整交付。** 显式 Mock 命令启动后，页面、交互与受测业务路径通过；默认完全无密钥启动和 Swagger 在线生成存在已复现的既有缺陷，真实模型与生产部署未验收。本次没有修改核心业务、依赖、安全策略或生产配置来掩盖这些限制。

## 前端模块与接口契约

入口为 frontend/src/main.ts；UserLayout 服务求职者，CompanyLayout / AdminLayout 封装共享 WorkspaceLayout，登录注册共用 AuthShell。页面采用动态导入，路由守卫读取 meta.requiresAuth / meta.roles。登录状态保存在 Pinia 与 localStorage 的 sr_token / sr_user；业务权限仍以后端为准。

request.ts 默认 baseURL=/api、超时 20 秒，附加 Bearer token 并解包 Result.data。401 清理状态并保留回跳地址，403 提示错误并保留有效登录。VITE_API_BASE 可在构建时覆盖网关。附件下载通过 download.ts 携带授权，不能把简历 URL 当作公开链接。

plugins/ui.ts 由 scripts/generate-ui.mjs 自动扫描并生成；本次生成 37 个组件、64 个图标，不手工编辑生成清单。ECharts 在 utils/echarts.ts 按用量注册；styles/index.css 与 pages.css 为现有公共样式。

详细路由见 [系统功能说明](系统功能说明.md#六前端页面路由)，开发约定见 [前端开发指南](../frontend/前端开发指南.md) 与 [界面规范](界面设计规范.md)。本次扫描 api 目录 82 处请求调用，方法与路径均存在后端映射；这是静态路径核对，不等同于所有参数/响应或动态调用的完整验收。

## 后端服务与 API

启动入口为 RecruitmentApplication。Controller 负责参数与角色校验，Service 负责业务归属、状态与事务，Mapper 使用 MyBatis-Plus。业务 JSON 采用 Result<T>，分页为 records/total/page/size；附件成功响应为文件流，图片与 Swagger 不使用 Result 包装。

日期时间实测采用带 T 的 ISO 字符串，前端格式化后展示；不把配置的 date-format 当作 LocalDateTime 的统一序列化保证。

## 数据库设计与业务不变量

sql/schema.sql 包含 16 张业务表；实体 @TableName 与驼峰字段到 SQL 列名的静态核对未发现缺列。基础字段与 ER 见 [数据库设计](数据库设计.md)，24 个增量索引及 18 项 CHECK 约束见 [数据库优化与扩展数据](数据库优化与扩展数据.md)。关系没有数据库外键，由服务层维护；逻辑删除只适用于带 deleted 的实体，不能认为所有表均逻辑删除。

关键规则：单用户/岗位投递唯一、收藏唯一、企业账号档案唯一，每份简历保留最新分析。推荐使用最新创建的简历，批次须全在 6 小时内并晚于简历更新时间；简历/岗位修改使缓存失效。单次匹配不更新推荐批次，投递评分仅保存到 job_application。分析、推荐、面试与登录助手记录落库；简历优化即时返回。

新库顺序为 schema.sql → data.sql → demo-data.sql。本次临时库导入结果为 53 个账号、14 家企业、89 个岗位，与历史本机总数不同；后者含开发测试数据，不混写为种子总数。已有库按专题文档使用 upgrade-ai-chat.sql、upgrade-database.sql 和 demo-data.sql；不使用 schema.sql 做日常升级。

## 认证授权与安全边界

JWT 使用 HS256，默认 168 小时；JwtAuthenticationFilter 会查询当前账号状态与角色，禁用或删除的账号不能继续使用旧 token。方法权限与 Service 归属校验共同限制数据访问。注册仅接受 USER/COMPANY；ADMIN 由初始化预置。

avatar/logo/image 公开；resume 附件需 JWT，允许本人、管理员或收到对应简历投递的企业，返回 no-store。扩展名与 20 MB 请求/文件限制来自 FileService 和 multipart 配置；不把扩展名过滤称为完整文件安全扫描。

默认 CORS 来源为 localhost 与 127.0.0.1 的 5173、5174 端口，可用 CORS_ALLOWED_ORIGINS 覆盖。模型配置接口只返回 hasApiKey，不回显密钥。默认演示账号、内置 JWT secret 与开发密码适用于本机演示；上线前必须独立设置，当前没有生产安全验收结论。真实模型可能收到简历与岗位内容，数据治理与供应商限制待生产评估。

## 安装运行构建与部署

首次准备数据库与前端安装见 [README](../README.md)。开发/预览默认 5173 / 127.0.0.1:5174，均代理 /api 到 localhost:8080（vite.config.ts）。Mock 后端使用：

```powershell
cd backend
mvn spring-boot:run '-Dspring-boot.run.arguments=--ai.enabled=false --ai.mock=true --spring.ai.openai.api-key=not-configured'
```

打包后可在 backend 目录执行：

```powershell
java -jar target/smart-recruitment-backend.jar --ai.enabled=false --ai.mock=true --spring.ai.openai.api-key=not-configured
```

占位值仅传给 spring.ai.openai.api-key，不应写作真实 AI_API_KEY，也不改变业务 realMode() 判断。已配置真实模型时，移除 Mock 参数并使用供应商配置；该路径本次未联网验证。

Compose 默认只启动 MySQL / Redis，--profile app 才包含后端与前端：

```powershell
docker compose up -d
docker compose --profile app up -d --build
```

当前文件声明 mysql:8.0、redis:7-alpine、Java 17、Node 22 构建与 nginx 前端。MySQL 空数据卷首次按 01/02/03 挂载 SQL 初始化；已有数据卷不重复导入。Compose MySQL 演示密码与 dev 密码不同；本地直连时需明确覆盖 spring.datasource.password 或使用相应 profile。

**这些 Docker 命令仅是配置中的运行入口，当前未验证可启动**：空密钥自动配置可能导致容器启动失败；Compose 尚未挂载后端上传目录，也未设置独立 JWT secret；镜像构建上下文无 .dockerignore，不能直接作为安全生产发布结论。修改部署关键路径需批准后再做。
