## 索引与约束

联合索引依据实际查询的等值条件、逻辑删除过滤和排序设计：

| 查询 | 新索引 |
| --- | --- |
| 在线岗位按发布时间/浏览数/薪资排序 | `idx_job_latest` / `idx_job_hot` / `idx_job_salary` |
| 岗位分类筛选、企业岗位列表 | `idx_job_type_latest` / `idx_company_jobs` |
| 用户、岗位、管理员投递列表 | `idx_application_user` / `idx_application_job` / `idx_application_admin` |
| 用户、岗位、投递趋势 | `idx_user_trend` / `idx_job_trend` / `idx_application_trend` |
| 简历与经历排序 | `idx_resume_owner` / `idx_experience_sort` |
| 用户、企业、举报后台列表 | `idx_user_list` / `idx_company_list` / `idx_report_list` |
| 收藏、推荐、面试历史、题目排序 | `idx_favorite_user` / `idx_recommendation_rank` / `idx_interview_history` / `idx_question_sort` |
| 日志时间筛选 | `idx_log_time` / `idx_log_type_time` |
| 助手会话和消息历史 | `idx_chat_history` / `idx_chat_messages` |

约束检查薪资非负且最低值不超过最高值、浏览量/题量/消息量非负、技能等级 1–5、权重大于 0、所有评分 0–100、逻辑删除值为 0 或 1。可选评分仍允许 NULL。

保留原有字段类型、JSON 字符串格式和服务层删除语义。未添加外键、未对简历所有者增加唯一键，以兼容多份简历及当前删除流程。模糊搜索使用 `%关键词%`，普通 B-tree 索引无法消除该条件的扫描。小规模演示数据上优化器可能选择全表扫描和 filesort；索引存在并不代表所有查询立即使用它，生产环境应根据数据量、EXPLAIN 和慢查询继续调整。

## 已有数据库升级

先备份，再按顺序执行，不能在已有数据库运行 `schema.sql`（该文件会删除业务表）：

```powershell
mysql -u root -p --default-character-set=utf8mb4 -e "source sql/upgrade-ai-chat.sql"
mysql -u root -p --default-character-set=utf8mb4 -e "source sql/upgrade-database.sql"
mysql -u root -p --default-character-set=utf8mb4 -e "source sql/demo-data.sql"
```

在项目根目录执行。前两项先补全旧版本缺失的助手表，再添加优化；最新库重复运行也可。增量脚本按对象名跳过已有索引及约束。DDL 会自动提交，如历史资料违反新约束，MySQL 会报错；修复相关记录后可以重跑。补充数据通过事务写入，失败时回滚，不使用 INSERT IGNORE 掩盖错误。请单次串行导入，`cn_demo_*` 前缀专用于演示数据。

## 新环境初始化

依次执行 `sql/schema.sql`、`sql/data.sql`、`sql/demo-data.sql`。Docker 已通过明确编号的文件挂载保证此顺序。已有 Docker 数据卷不会自动再次导入，应在容器中执行上述增量脚本，无需删除数据卷。

## 验证与重新生成

`scripts/verify-database.cjs` 创建独立临时库，验证全新建库、两次导入行数一致、关联和所有者完整、会话/题目数量一致，以及薪资、评分、技能和删除标记的非法值拦截；最后自动删除临时库，不改动业务库。需要创建/删除临时数据库的权限。

```powershell
# MYSQL_PWD 通过环境变量提供；可选 MYSQL_BIN、MYSQL_HOST、MYSQL_PORT、MYSQL_USERNAME。
node scripts/verify-database.cjs
```

生成器只写入 SQL 文件，不连接数据库：

```powershell
node scripts/generate-database-upgrade.cjs
node scripts/generate-demo-data.cjs
```

已在 MySQL 8.0.41 验证通过，本地增量脚本重复执行后用户、企业、岗位、简历和投递总数保持一致。
