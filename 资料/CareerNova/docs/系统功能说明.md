# 智能招聘网站（智聘 AI）—— 系统功能说明

> 文档更新：2026-10-08。文件名与引用按当前目录同步；验收记录标注的是历史验证，本轮未重新执行业务测试。 总入口：[项目总文档](项目总文档.md)。

> 项目技术形态：Spring Boot 3 + Vue 3 前后端分离，以人工智能为核心特色的招聘网站。
> 本文说明系统功能组成、角色权限、前端路由与答辩演示流程。接口细节见[接口说明](接口说明.md)，AI 实现见[人工智能功能说明](人工智能功能说明.md)，数据模型见[数据库设计](数据库设计.md)。

## 一、项目定位

系统面向求职者（USER）、企业招聘人员（COMPANY）和平台管理员（ADMIN）三类角色。AI 能力不是独立聊天入口，而是嵌入简历解析、简历评估、岗位检索与推荐、投递筛选和模拟面试等招聘流程。

主要特点：

- **六项核心 AI 能力**：简历分析、岗位匹配、岗位推荐、简历优化、AI 模拟面试、AI 智能助手（页面右下角悬浮对话框）；企业端另有候选人 AI 分析。
- **Mock / 真实模型双模式**：默认 `ai.mock=true`，无需 API Key 即可离线演示；配置真实模型后切换为 LLM + Embedding，调用失败会自动回退规则引擎。
- **角色与数据隔离**：JWT 鉴权、方法级角色权限、简历/投递/面试等资源归属校验。
- **可选 Redis**：Redis 不可用时自动降级为本地内存缓存，不影响核心业务。
- **可部署演示**：提供 MySQL 初始化脚本和 Docker Compose，可单独启动基础设施或构建全栈环境。

## 二、角色功能清单

### 2.1 求职者（USER）

| 功能域 | 当前能力 |
| --- | --- |
| 账号 | 注册、登录、查看和修改个人资料、修改密码、上传头像 |
| 简历 | 创建多份简历，维护基本信息、技能、个人简介和教育/工作/项目/实习经历；上传 PDF/DOCX/DOC/TXT 附件 |
| 简历解析 | 从已上传附件提取文本，预览姓名、联系方式、学历、技能和经历，核对并保存后重算完整度 |
| 简历分析 | 生成综合、技能、经验、学历、完整度五维报告；结果按简历保留最新一条，可重复分析覆盖 |
| 岗位浏览 | 按关键词、城市、类型、学历、经验和薪资检索在线岗位，查看岗位详情；详情访问会增加浏览量 |
| 岗位匹配 | 对当前简历与指定在线岗位计算语义、技能、经验和学历匹配分，展示命中/缺失技能与推荐理由 |
| 岗位推荐 | 根据最近一份简历和在线岗位生成推荐列表；正常读取 6 小时内的持久化结果，也可手动刷新 |
| 简历优化 | 对照目标岗位 JD，返回个人简介、项目/工作经历和技能关键词的原文与优化建议；结果即时返回，不落库 |
| 投递 | 选择简历投递岗位，查看投递记录和状态，撤销仍为 PENDING 的投递 |
| 收藏 | 收藏或取消收藏岗位，分页查看收藏列表，岗位详情返回是否已收藏 |
| AI 模拟面试 | 选择岗位、难度和题量开始面试，逐题作答获取评分点评，结束后生成维度报告并查看历史记录 |
| AI 智能助手 | 页面右下角悬浮气泡：智能问答（简历/岗位/面试/投递全流程）、查看推荐追问、对话记录；登录后自动保存，未登录可直接问答 |
| 举报 | 举报岗位或企业，查看本人举报记录及处理状态 |

## 三、核心业务规则

1. **注册与账号**：注册仅接受 USER 和 COMPANY，ADMIN 由 `sql/data.sql` 预置。账号状态包括 ENABLED 和 DISABLED，禁用账号登录返回 403。
2. **JWT 认证**：登录后签发 HS256 JWT，claims 包含 `sub`、`uid`、`nickname` 和 `role`，默认有效期由 `app.jwt.expire-hours` 控制，当前为 168 小时。
3. **岗位状态**：公开列表和详情只允许匿名用户查看 ONLINE 岗位；企业端和后台可按权限查看、管理 OFFLINE 岗位。
4. **投递约束**：`job_application` 对 `(user_id, job_id)` 建唯一键，同一用户不能重复投递同一岗位；企业不能把状态改回 PENDING。
5. **收藏约束**：`favorite` 对 `(user_id, job_id)` 建唯一键，重复收藏会被拦截。
6. **简历归属**：简历、简历解析、简历分析、简历优化、投递和 AI 面试均校验当前登录用户的数据归属。
7. **简历完整度**：由姓名、手机、邮箱、学校、学历、专业、技能数量、简介、经历和附件等 10 项计算，每项 10 分，封顶 100 分。
8. **推荐缓存**：推荐结果写入 `ai_recommendation`；整批结果须在 6 小时内且晚于最新简历更新时间；简历和岗位变更会使推荐失效，GET 过滤下架/删除岗位，POST refresh 强制重算。
9. **AI 降级**：真实模型超时、网络异常或结构化结果解析失败时，业务服务回退规则实现，正常接口仍保持可用。
10. **健康检查**：`GET /api/common/health` 返回 MySQL、Redis 和 AI 模式，用于本地运行与答辩现场快速验证。

## 四、AI 功能与数据持久化

| AI 功能 | 主要入口 | 结果处理 |
| --- | --- | --- |
| 简历解析 | `POST /api/resume/{id}/parse` | 返回 `ResumeParseVO` 预览，核对后保存 |
| 简历分析 | `POST /api/ai/resume/analyze/{resumeId}`、`GET /api/ai/resume/analysis/{resumeId}` | 写入 `ai_resume_analysis`，按简历保留最新一条 |
| 岗位匹配 | `POST /api/ai/match` | 实时返回匹配结果，不改写 `ai_recommendation` 推荐批次 |
| 岗位推荐 | `GET /api/ai/recommendations`、`POST /api/ai/recommendations/refresh` | 写入 `ai_recommendation`，返回 Top N |
| 简历优化 | `POST /api/ai/resume/optimize` | 即时返回优化对比，不持久化 |
| AI 模拟面试 | `/api/ai/interview/*` | 场次、题目、答案、评分和报告写入 `ai_interview`、`ai_interview_question` |
| 企业候选人分析 | `GET /api/company/candidates/{applicationId}/analysis` | 基于当前简历和岗位实时计算，不单独落库 |
| AI 智能助手 | 右下角悬浮气泡：`/api/ai/chat/greeting`、`/api/ai/chat/ask`、`/api/ai/chat/history` | 登录后会话与消息写入 `ai_chat_session`、`ai_chat_message`（含推荐追问）；未登录问答不落库 |

说明：`AiAnalysisVO.source` 和 `MatchResultVO.source` 在实时计算接口中返回执行来源；匹配支持 LLM / RULE / FALLBACK；分析报告的 GET 接口从数据库组装结果时不会恢复 `source`，前端不应把它作为持久化字段依赖。

## 五、权限与安全

1. **公开路径过滤器白名单**：`/api/auth/**`、`/api/home/**`、`/api/common/**`、`/api/jobs/**`、`/api/companies/**`、`/api/files/avatar/**`、`/api/files/logo/**`、`/api/files/image/**`、`/api/ai/chat/greeting`、`/api/ai/chat/ask`、`/api/ai/chat/history`、Swagger 相关路径等。
2. **方法级权限仍然生效**：白名单只说明请求能进入 Controller，不代表全部匿名可用。例如 `GET /api/auth/me` 和 `POST /api/files/upload` 仍要求登录；公开访问主要是岗位、企业、首页统计、健康检查和公开图片；简历附件需登录并校验归属或企业投递关系。
3. **角色控制**：接口通过 `@PreAuthorize` 校验 ROLE_USER、ROLE_COMPANY 或 ROLE_ADMIN。
4. **资源归属**：非本人简历、投递或面试按接口语义返回 404/403；企业只能分析本企业岗位收到的投递。
5. **文件上传**：通用上传接口及头像、Logo、简历附件接口均要求登录；文件大小上限 20MB，允许扩展名按上传类别限制。
6. **CORS**：默认允许 localhost 与 127.0.0.1 的 5173、5174 两个端口，可用 `CORS_ALLOWED_ORIGINS` 覆盖，允许常用 HTTP 方法，并暴露 `Authorization` 响应头。
7. **统一响应**：业务 JSON 接口返回 `Result<T>`，分页使用 `PageResult<T>`；成功附件下载返回文件流，公开图片不使用 Result。前端同时处理业务码与 HTTP 错误。
8. **日志**：登录成功/失败写入 LOGIN，`@OpLog` 业务操作当前写入 OPERATE，未捕获异常写入 ERROR；AI 类型保留为日志枚举，初始化数据中包含 AI 示例记录。

## 七、答辩演示建议

> 前置：完成数据库初始化并启动后端（8080）和前端（5173）。推荐账号密码均为 `123456`：求职者 `user`、企业 `company`、管理员 `admin`。

### 演示一：AI 岗位推荐与匹配

1. 使用 `user` 登录，在首页或 `/recommend` 查看推荐岗位。
2. 打开“Java开发工程师”岗位详情，查看匹配度、命中技能和缺失技能。
3. 进入 `/recommend/{jobId}`，说明综合公式：语义 50% + 技能 25% + 经验 15% + 学历 10%。
4. 强调真实模式使用 Embedding 语义向量，Mock 模式使用本地 n-gram 向量；推荐批次写入 `ai_recommendation` 并支持 6 小时缓存；单次匹配即时返回，不写入推荐批次。

### 演示二：简历上传、解析与分析

1. 在 `/resume/edit` 上传 PDF/DOCX/TXT 简历。
2. 点击 AI 解析预览，确认进入编辑页核对内容，保存后查看完整度变化。
3. 执行 AI 简历分析，展示五维评分、优势、不足、建议和目标岗位方向。
4. 说明分析结果写入 `ai_resume_analysis`，刷新后仍可通过 GET 读取；同时提醒 `source` 只在实时分析响应中返回。

### 演示三：岗位定向简历优化

1. 从岗位详情发起简历优化，选择当前简历。
2. 对照展示原文、优化后文本、修改说明和建议关键词。
3. 说明该功能即时返回，不写入数据库，适合用户确认后自行修改简历。

### 演示四：AI 模拟面试

1. 在 `/ai/interview` 新建面试，选择岗位、难度和题量。
2. 逐题作答，展示即时评分与点评。
3. 结束后生成总分、题型维度分、优势、不足和复习建议。
4. 说明场次、题目、答案和报告均写入数据库，历史记录可随时回看。

### 补充演示

- 企业端：使用 `company` 登录，处理投递状态，并对候选人执行 AI 分析。
- 管理端：使用 `admin` 登录，查看统计看板、处理举报、检查日志和 AI 配置。
- 健康检查：访问 `GET http://localhost:8080/api/common/health`，确认 MySQL、Redis 与 AI 模式。
