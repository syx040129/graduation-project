# 智能招聘网站 —— 接口说明

> 文档更新：2026-10-08。文件名与引用按当前目录同步；验收记录标注的是历史验证，本轮未重新执行业务测试。 总入口：[项目总文档](项目总文档.md)。

> 依据当前后端 Controller、DTO、统一响应与配置整理，覆盖全部接口，共 **83 个 Controller 方法/路径组合**（含受保护的简历下载，不含静态资源与 Swagger）。所有 HTTP/JSON body 均为 UTF-8。

## 一、通用约定

### 1.1 基础信息

- Base URL：`http://localhost:8080`（server.port=8080，无 context-path；生产可用 SERVER_PORT 环境变量覆盖）。
- 请求体：JSON，`Content-Type: application/json`；文件上传使用 `multipart/form-data`。
- 时间格式：LocalDateTime 实测为 ISO 字符串（如 `2026-10-07T20:21:36`）；application.yml 的 date-format 不保证 Java 时间类型使用空格分隔。前端格式化工具将 T 替换为空格并截取日期/时间，接口不附带时区偏移。
- 当前业务异常与认证处理通常以 HTTP 200 返回 `Result.code`；CORS 拒绝、网关和容器错误仍可能使用非 2xx HTTP 状态。前端请求层同时处理业务码与 HTTP 错误，不能只检查 HTTP 200。
- JWT 请求头：`Authorization: Bearer <token>`（前端需自行加 Bearer 前缀；登录接口返回的 token 为原始 JWT 字符串）。

### 1.2 统一响应包装 Result<T> 与分页 PageResult<T>

业务 JSON 接口包一层 Result；成功的附件下载返回文件流，公开图片与 Swagger 资源也不使用该包装：

```json
{ "code": 200, "message": "success", "data": ... }
```

- 成功：code=200、message="success"；失败：data 为 null。
- 分页数据放于 data 内（PageResult<T>，page 从 1 开始）：

```json
{ "records": [], "total": 0, "page": 1, "size": 10 }
```

### 1.3 错误码表

| code | 含义 | 典型场景 |
| --- | --- | --- |
| 200 | 成功 | - |
| 400 | 参数/业务错误 | 校验失败、业务规则不满足、格式错误 |
| 401 | 未登录 | 未携带或携带无效 token |
| 403 | 无权限 / 被禁用 | 角色不符、账号 DISABLED |
| 404 | 不存在 | 资源不存在或非本人资源 |
| 409 | 冲突 | 用户名已存在、重复投递/收藏等重复数据 |
| 500 | 服务器内部错误 | 未捕获异常 |
| 503 | AI 服务错误 | AI 服务调用失败 |

### 1.4 错误信息示例（GlobalExceptionHandler）

- 未带 token 访问受保护接口：`{"code":401,"message":"请先登录","data":null}`
- 无权限 / 角色不符：`{"code":403,"message":"没有操作权限","data":null}`
- 业务异常：`{"code":400|404|409|503,"message":"业务文案","data":null}`
- 参数校验失败（@Valid）：`{"code":400,"message":"<第一个字段的错误消息>"}`（如 用户名不能为空）
- 参数格式错误 / 缺参 / 类型不匹配：`{"code":400,"message":"请求参数格式错误: ..."}`
- 重复键（唯一约束冲突）：`{"code":409,"message":"数据已存在，请勿重复操作"}`
- 数据关联冲突：`{"code":400,"message":"数据操作冲突，请检查关联数据"}`
- 上传超过 20MB：`{"code":400,"message":"上传文件不能超过 20MB"}`
- 路径不存在：`{"code":404,"message":"接口不存在: <resourcePath>"}`
- 请求方法不支持：`{"code":400,"message":"不支持的请求方式: <METHOD>"}`
- 未捕获异常：`{"code":500,"message":"服务器内部错误，请稍后重试"}`

### 1.5 认证与角色

- 注册仅允许角色 USER（求职者）或 COMPANY（企业）；ADMIN 不能自助注册，只能由管理员预置。
- 角色（JWT claim role，Spring 权限 ROLE_<role>）：USER / COMPANY / ADMIN。
- 本文接口标注：[public] 匿名可访问；[auth] 任意已登录用户（含 ADMIN）；[USER] 仅 ROLE_USER；[COMPANY] 仅 ROLE_COMPANY；[ADMIN] 仅 ROLE_ADMIN（标注于小节标题时表示整组接口要求该角色）。
- SysUser.status：ENABLED 正常 / DISABLED 禁用（禁用账号登录返回 403“账号已被禁用，请联系管理员”）。
- JWT：HS256，claims sub=username、uid、nickname、role；默认有效期 app.jwt.expire-hours=168（7 天）。
- 登录成功与否写入 LOGIN；`@OpLog` 标注的业务操作当前写入 OPERATE；未捕获异常写入 ERROR。AI 类型是日志枚举，当前代码中的 AI 注解端点也由操作切面记录为 OPERATE。

### 1.6 安全白名单与 CORS

无需 token 即可命中 controller 的路径前缀（SecurityConfig.PUBLIC_PATHS）：

```
/api/auth/**   /api/home/**   /api/common/**   /api/jobs/**   /api/companies/**
/api/files/avatar/** /api/files/logo/** /api/files/image/**  /v3/api-docs/**  /swagger-ui/**  /swagger-ui.html  /doc.html
/api/ai/chat/greeting   /api/ai/chat/ask   /api/ai/chat/history
/favicon.ico   /error
```

注意：白名单只放行过滤器层，**方法级 @PreAuthorize 仍然生效**，因此：

- `GET /api/auth/me` 虽位于 /api/auth/**，仍需带 token，否则 403“没有操作权限”；
- `POST /api/files/upload` 不在公开白名单内且方法要求登录；只有 avatar/logo/image 的静态 GET 公开；resume 附件需 JWT，并校验简历所有者、管理员或接收该简历投递的企业；
- `GET /api/jobs/**`、`GET /api/companies/**`、`/api/home/**`、`/api/common/**` 公开。

CORS：默认允许 localhost 与 127.0.0.1 的 5173、5174 两个端口，可用 `CORS_ALLOWED_ORIGINS` 覆盖来源列表；方法 GET/POST/PUT/DELETE/OPTIONS；请求头 *；暴露响应头 Authorization；allowCredentials=true；maxAge 3600s。

### 1.7 文件上传规则（FileService）

- 通用上传：`POST /api/files/upload` [auth]，multipart 字段 `file`（文件）+ `category`（类别），返回 `data: { url }`。
- 类别与扩展名白名单：

| category | 允许扩展名 |
| --- | --- |
| avatar / logo / image | jpg jpeg png gif webp |
| resume | pdf doc docx txt（doc 可上传，但简历解析不支持旧版 .doc） |

- 大小上限：spring.servlet.multipart max-file-size / max-request-size = 20MB。
- 保存位置：`${app.upload-dir:./uploads}`（默认后端运行目录下 ./uploads）。
- 静态映射（WebMvcConfig）：avatar/logo/image 分类映射到磁盘 uploads 对应目录；resume 由受权限保护的下载 Controller 提供。
- URL 生成规则：`/api/files/{category}/{yyyyMM}/{UUID去横线}.{ext}`，例：`/api/files/resume/202609/3f2a...9c.pdf`。

## 二、认证模块 Auth（/api/auth）3 个

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | /api/auth/register | [public] | 注册（USER/COMPANY） |
| POST | /api/auth/login | [public] | 登录，返回 token + 用户信息 |
| GET | /api/auth/me | [auth] | 当前登录用户信息 |

**① POST /api/auth/register**

请求体：`{ "username": "…", "password": "…", "nickname": "…", "phone": "…", "email": "…", "role": "USER"|"COMPANY" }`

- username：4-20 位，正则 `^[a-zA-Z0-9_]{4,20}$`；password：6-30 位。
- nickname ≤30；phone 为空或 `^1[3-9]\d{9}$`；email 可选。
- 返回 data：UserProfileVO（注册成功不返回 token）；用户名重复 code=409“用户名已存在”。
- COMPANY 注册自动创建企业档案，企业名取 nickname，缺省用 username。

**② POST /api/auth/login**

请求体：`{ "username": "…", "password": "…" }` → data：`{ "token": "<原始JWT>", "user": UserProfileVO }`

- 用户名或密码错误：400“用户名或密码错误”；账号禁用：403“账号已被禁用，请联系管理员”。
- 请求时把 token 放入 `Authorization: Bearer <token>`。

**③ GET /api/auth/me** → data：UserProfileVO（见 §6.1）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/resume/list | 当前用户全部简历（按 id 倒序） |

| POST | /api/resume | 创建简历（可提交空表单） |

ExperienceForm：`{ id?(保存时忽略), type(必填 EDUCATION/WORK/PROJECT/INTERNSHIP), title(必填≤100), company?(≤100), content?, startDate?(≤20 如 2020-09), endDate?(≤20), sort?(缺省按数组顺序 0,1,2...) }`

### 5.1 ResumeVO

| 字段 | 类型/说明 |
| --- | --- |
| id / userId | Long |
| name / phone / email | String（电话≤20、邮箱≤100） |
| education / school / major | String |
| skills | string[] |
| summary | String |
| resumeFileUrl | String? |
| completionScore | int 0-100 完整度 |
| createTime / updateTime | 时间 |
| experiences | ResumeExperience[]（全量字段：id, resumeId, type, title, company, content, startDate, endDate, sort） |

### 5.2 简历解析流程（POST /api/resume/{id}/parse）

1. 校验已上传文件：未上传 400“请先上传简历文件”；磁盘文件缺失 400“简历文件不存在，请重新上传”。
2. DocumentTextExtractor 按扩展名抽取文本：pdf→PDFBox；docx→POI（段落+表格）；txt→UTF-8（失败退回 ISO-8859-1）；doc→400“暂不支持旧版 .doc 文件，请另存为 .docx 后再上传”。
3. ResumeTextParserService.parse(text)：真实 AI 模式（ai.enabled=true 且 mock=false）→ LLM 结构化 JSON；否则 Mock/规则模式（正则抽手机号/邮箱 + 技能关键词表）。
4. 返回结构化解析预览，不更新字段、不覆盖技能、不删除旧经历。
5. 前端展示预览，用户确认进入编辑页：补齐空字段、合并技能，保留已有经历。
6. 用户核对后调用 PUT /api/resume/{id} 保存，保存时重算完成度并使推荐失效。

ResumeParseVO：`{ resumeId, fileName(服务器存储文件名), fileUrl, text(原文前 3000 字), filled(恒 false，预览尚未保存), name, phone, email, education, school, major, summary, skills(string[]), experiences(ExperienceForm[]，未持久化) }`

## 二十九、管理后台 —— AI 配置（/api/admin/ai）2 个，均 [ADMIN]

**㉞ GET /api/admin/ai/config** → data: Map（反映 AiProperties 字段，密钥脱敏）：

```json
{
  "mode": "REAL", "enabled": true, "mock": false,
  "baseUrl": "https://api.openai.com", "model": "gpt-4o-mini",
  "embeddingModel": "text-embedding-3-small", "embeddingEnabled": true, "hasApiKey": true,
  "recommendPoolSize": 20, "recommendLimit": 10
}
```

- mode 判定：enabled && !mock && hasApiKey → REAL；mock=true → MOCK；否则 DISABLED。
- hasApiKey 仅返回是否存在密钥，**不返回明文**。
- `embeddingEnabled=false` 时即使处于真实模式，语义匹配也使用本地向量；`baseUrl` 通常填写根地址，不要手动追加 `/v1`，Spring AI 会按 OpenAI 兼容协议拼接接口路径。
- 注意：后端**没有**“更新配置”端点——配置只读自 application.yml 的 ai.* 前缀；前端将 config 视为只读展示并提供“测试连通性”按钮即可。

**㉟ POST /api/admin/ai/test**（无 body）→ data: Map：

```json
{
  "mode": "REAL", "ok": true, "message": "模型连接成功",
  "reply": "……（真实模式成功时的模型回复，>50 字符截断加 ...）", "latencyMs": 823
}
```

- MOCK 模式：ok=true，message 提示“Mock 模式无需外部模型”，reply/latencyMs 为 null。
- REAL 模式：发起一次真实对话验证连通性；失败 ok=false 并给出失败说明。

## 三十二、Swagger 使用说明

> 2026-10-08 收尾实测：`/v3/api-docs` 返回 `Result.code=500`，日志为 `ControllerAdviceBean(Object)` 的 `NoSuchMethodError`。当前 SpringDoc 2.6.0 与运行框架存在兼容问题，在线接口生成未通过；以下是修复后的使用方式，当前以 Controller 源码及本文查阅接口。详见 [总文档](项目总文档.md#已知问题与待批准方案)。

1. 后端启动后访问 http://localhost:8080/swagger-ui.html（OpenAPI JSON：http://localhost:8080/v3/api-docs）。
2. 修复在线文档兼容问题后，HTTP bearer 方案的 Authorize 输入原始 token，Swagger 自动添加 Bearer 前缀（先调用 /api/auth/login 获取 token）。
3. 建议演示/联调顺序：login 获取 token → 带 token 调用本人资源接口（简历/投递/AI 等）→ 用 company 账号测试企业侧接口 → 用 admin 账号测试管理端接口与 AI 配置。
4. 若 Swagger 页面无分组显示，可参考本契约文档按模块检索；业务参数校验与响应结构以契约描述为准。
