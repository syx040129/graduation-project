# 智能招聘网站 —— 数据库设计

> 文档更新：2026-10-08。文件名与引用按当前目录同步；验收记录标注的是历史验证，本轮未重新执行业务测试。 总入口：[项目总文档](项目总文档.md)。

> 数据库：smart_recruitment（MySQL 8.0，InnoDB，utf8mb4 / utf8mb4_unicode_ci）
> 脚本：sql/schema.sql（建库建表）与 sql/data.sql（初始化数据），schema.sql 创建数据库，数据脚本使用该库，按顺序导入即可。
> 警告：schema.sql 会先 DROP TABLE IF EXISTS 再重建业务表，重复执行会清空现有数据；仅用于首次初始化或确认可以重置数据库时。
> 2026-10-08 新增 24 个索引和 18 项 CHECK 约束，并补充扩展演示数据；已有库使用 `sql/upgrade-database.sql`、`sql/demo-data.sql`，详见 [数据库优化与扩展数据](数据库优化与扩展数据.md)。新库依次执行 schema.sql、data.sql、demo-data.sql。
> 约定：业务表使用 BIGINT 自增主键；通用字段 create_time/update_time（DATETIME，自动维护）；逻辑删除字段 deleted（0 正常 / 1 删除，由 MyBatis-Plus 全局逻辑删除配置接管，业务查询自动过滤）。

## 三、schema.sql 设计约定

1. **字符集**：数据库与表统一 utf8mb4 + utf8mb4_unicode_ci，兼容中文与 emoji。
2. **主键**：全部 InnoDB 表使用 BIGINT AUTO_INCREMENT 主键；字段命名 snake_case，由 MyBatis-Plus map-underscore-to-camel-case 映射为驼峰属性。
3. **逻辑删除**：核心业务表带 deleted 字段；application.yml 中配置 MyBatis-Plus 全局逻辑删除（logic-delete-field=deleted，1=已删，0=未删），代码中无需手工拼接条件。
4. **唯一约束**：uk_username（用户名唯一）、uk_user_id（企业与账号一对一）、uk_user_job（job_application 与 favorite、ai_recommendation 均防重复）、uk_resume_id（每份简历仅保留一条最新分析）。
5. **普通索引**：为高频查询建立联合/单列索引，如 job(idx_company、idx_status_city(status, city))、sys_user(idx_role_status) 等，具体见逐表说明。
6. **外键策略**：**不使用数据库外键**，表与表之间仅建立索引，业务关系、级联删除与完整性校验在代码层（Service/事务）维护——避免外键对写入性能与代码演进的影响，也便于逻辑删除与批量导入。
7. **初始化脚本可重复执行但会重置数据**：schema.sql 先 DROP TABLE IF EXISTS 再建表，data.sql 随后批量 INSERT，因此按顺序重新导入可以得到相同的初始状态，但会清空已有的业务数据，不能把它当作无损升级脚本。

## 四、表关系说明（ER 文字版）

```
sys_user (USER/COMPANY/ADMIN)
  │ 1:0..1（COMPANY 注册自动建档）
  ▼
company ──1:N──> job ──1:N──> job_skill（岗位技能）
  │
sys_user ──1:N──> resume ──1:N──> resume_experience
  │                     │1:0..1
  │                     ▼
  │              ai_resume_analysis（每次分析先删后插）
  │
sys_user ──1:N──> job_application（job_id, resume_id 关联；uk_user_job 防重复）
sys_user ──1:N──> favorite（uk_user_job 防重复）
sys_user ──1:N──> ai_recommendation（推荐打分，uk_user_job）
sys_user ──1:N──> ai_interview ──1:N──> ai_interview_question
sys_user ──1:N──> report（举报，无唯一约束）
sys_user ──1:N──> ai_chat_session ──1:N──> ai_chat_message（AI 助手对话记录）
sys_log（游离表：记录任意用户与操作，不设外键）
```

关系要点：

- sys_user 与 company 一对一：企业角色注册后自动创建企业档案（uk_user_id 保证一个账号一份）。
- company 与 job 一对多，job 与 job_skill 一对多；job_skill 为岗位技能画像，是 AI 技能匹配与缺失技能判定的数据基础。
- resume 经历整体重建：保存简历时服务端先删该简历全部 resume_experience 再批量插入，因此经历表不需要逻辑删除。
- job_application 唯一键 (user_id, job_id) 保证同一用户对同一岗位只能有一条投递；企业处理更新状态；求职者撤销 PENDING 投递执行逻辑删除。唯一键不含 deleted，撤销后重新投递仍可能被唯一键拒绝，当前未改变此业务行为。
- ai_resume_analysis 唯一键 resume_id：每次 AI 分析“先删后插”，始终保留最新报告；GET 查询直接读取持久化行。
- ai_recommendation 唯一键 (user_id, job_id)：单次岗位匹配不落库；岗位推荐刷新（POST /api/ai/recommendations/refresh）则清空该用户全部推荐后插入 Top N。
- ai_interview 与 ai_interview_question 一对多：题目随场次生成并入库；面试报告以 JSON 存于 ai_interview.report。
- report 与 sys_log 为治理类表：分别承载举报工单与登录/操作/AI/异常日志，前端后台分页展示。

## 六、导入方式与注意事项

1. 依次导入（先 schema 后 data）：`mysql -uroot -p < sql/schema.sql`，再 `mysql -uroot -p < sql/data.sql`；两脚本均自含 CREATE DATABASE/USE smart_recruitment。
2. 本地默认连接配置（application-dev.yml）：`jdbc:mysql://localhost:3306/smart_recruitment`，用户名/密码 root/123456（本仓库已按此配置）；若本机 root 密码不同，请同步修改 application-dev.yml 的 spring.datasource.password 或使用 Docker 启动。
3. Docker 方式：`docker compose up -d` 首次启动时 mysql 容器会按编号执行 schema.sql、data.sql、demo-data.sql 三个挂载脚本（仅空数据卷时初始化；如需重置可 `docker compose down -v` 后重来）。
4. 简历附件（resume_file_url）指向系统上传目录（默认 ./uploads，URL 前缀 /api/files/...）；种子数据的附件地址仅为示例，若演示“上传解析”请现场上传真实 PDF。
5. 时间字段由 MySQL 自动维护默认值（CURRENT_TIMESTAMP / ON UPDATE CURRENT_TIMESTAMP），应用层无需手工写入。
6. 演示与统计相关的 AI 结果中，简历分析、岗位推荐、面试场次/题目/报告与 AI 智能助手会话/消息会真实落库，可在数据库表中核对；单次岗位匹配与简历优化是即时返回结果，不写入推荐表或单独结果表；投递时的匹配分只保存至投递记录。`source` 仅在实时计算响应与 `ai_chat_message` 中返回/保存，不存于其他 AI 结果表。
7. **旧库升级（不重置数据）**：若数据库是早期版本初始化的，缺少 AI 智能助手两张表，可只执行增量脚本 `mysql -uroot -p < sql/upgrade-ai-chat.sql`（内部使用 CREATE TABLE IF NOT EXISTS，不影响既有数据）；全新初始化无需执行，schema.sql 已包含这两张表。
